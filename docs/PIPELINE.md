# CV-пайплайн meme.cv

Реализация: [`tracker.ts`](../src/lib/tracker.ts), [`cat-features.ts`](../src/lib/cat-features.ts), [`matching.ts`](../src/lib/matching.ts).

## 1. Камера и цикл обработки

Пользователь запускает `getUserMedia` с `audio: false`. Предпочтительное разрешение 640×480, камера фронтальная. Это пожелания браузеру, а не фиксированные параметры устройства.

Видео подключается к `<video playsInline muted>`. После разрешения доступа превью появляется сразу. Модели загружаются отдельно. Для доступа нужен HTTPS или localhost.

`requestAnimationFrame` обслуживает цикл. Анализ выполняется только для нового видеокадра и при интервале не меньше 65 мс. Face → Pose → Gesture выполняются последовательно на CPU/WASM в основном потоке. Реальная частота зависит от времени inference и устройства. React-состояние диагностики обновляется с интервалом больше 100 мс; Canvas рисуется после анализа.

При остановке закрываются media tracks и уже созданные модели, отменяется animation frame. Счётчик поколения не даёт завершившейся старой инициализации запустить новый цикл. Сетевые запросы загрузчика не привязаны к этому счётчику и могут завершаться в фоне после отмены.

## 2. Выход моделей

| Модель | Настройка | Используемые данные |
|---|---|---|
| Face Landmarker | VIDEO, одно лицо | Landmarks, blendshapes, facial transformation matrix |
| Pose Landmarker Lite | VIDEO, одна поза | Плечи, локти, запястья, visibility |
| Gesture Recognizer | VIDEO, до двух кистей | Landmarks, world landmarks, canned gesture categories |

Отдельный Hand Landmarker не запускается: точки кистей уже выдаёт Gesture Recognizer.

Важная деталь контракта: у точек лица и кистей поле `visibility` может равняться нулю и не быть показателем видимости. Поэтому эти точки проверяются по конечным координатам. Для позы остаётся порог `visibility >= 0.5`. Регрессионные тесты используют реальные числовые выходы моделей с нулевой visibility.

## 3. Нормализованные признаки

`Features` является частичным объектом. Значения ограничиваются диапазоном `[0, 1]`. Отсутствующий признак не заменяется нулём:

```ts
{ mouthOpen: 0, fist: undefined }
// Рот наблюдается закрытым; данных для оценки кулака нет.
```

| Признак | Источник |
|---|---|
| `mouthOpen` | `clamp((jawOpen - 0.02) / 0.55)` |
| `eyesOpen` | Среднее по глазам: `0.65 × (1 - eyeBlink) + 0.35 × eyeWide` |
| `headDown`, `headUp` | Pitch из матрицы лица; геометрический fallback |
| `leftHandUp`, `rightHandUp` | Высота запястья относительно плеч, нормированная расстоянием плеч |
| `handsNearFace` | Расстояние кисти/запястья до лица с нормированием по лицу или плечам |
| `fist` | Learned `Closed_Fist` + геометрия + персональные образцы при наличии |
| `callMe` | Геометрия 🤙 |
| `fingersTogether` | Геометрия 👉👈 для пары кистей |
| `tongueOut` | Анализ crop рта + подтверждение во времени |

`smile` и `browRaise` доступны в трекере и сглаживании, но не используются при подборе котов.

### Геометрия кистей

Предпочтительны world landmarks. При их отсутствии координаты x/z корректируются с учётом aspect ratio видео. Метрики нормируются по размеру ладони.

Разгибание пальца учитывает углы MCP/PIP/DIP, длину цепочки, расстояние кончика от основания и от запястья. Это уменьшает зависимость от ориентации руки и случаи, когда согнутый палец кажется прямым по одному углу.

- **Кулак:** максимум между `Closed_Fist`, геометрическим сгибом и совпадением с сохранёнными образцами. Уверенный `None` не обнуляет геометрию. Известные конфликтующие классы (`Thumb_Up`, `Open_Palm` и другие) подавляют fallback.
- **🤙:** большой палец отведён от ладони, мизинец выпрямлен, центральные пальцы согнуты. Прямой сустав большого пальца не обязателен.
- **👉👈:** кончики указательных пальцев близки, пальцы разогнуты и направлены примерно навстречу друг другу.

Слияние выполняется отдельно для каждой кисти. Затем берётся максимум по кистям: одна рука не должна подавлять другую. Персональные образцы кулака поддерживаются ядром и форматом сохранения; отдельной кнопки их записи в текущем минимальном UI нет.

## 4. Язык

Реализация: [`tongue.ts`](../src/lib/tongue.ts), [`tongue-calibration.ts`](../src/lib/tongue-calibration.ts), [`tongue-evidence.ts`](../src/lib/tongue-evidence.ts).

### Без калибровки

1. По точкам лица выбирается область рта и щёк с запасом для выступающего языка.
2. Crop уменьшается максимум до 192×192, без увеличения исходного разрешения.
3. Координаты переводятся в систему рта: ось между уголками компенсирует наклон головы в плоскости изображения.
4. Для пикселей рта и центральной области ниже губ вычисляются отношения RGB относительно кожи щёк. Это частично компенсирует экспозицию и баланс белого.
5. Отбрасываются слишком тёмные пиксели и участки вне области интереса.
6. В бинарной маске ищутся связные компоненты. Кандидат должен касаться нижней центральной части рта и иметь достаточную высоту/площадь. При почти закрытых губах требуется выступающая часть.
7. Площадь компонента преобразуется в ограниченный числовой score.

Это цветовая эвристика, не семантическая сегментация языка. Помада, еда, цветные источники света, тени и перекрытия могут приводить к ошибкам. Простое открытие рта не считается языком.

### С персональным профилем

Калибровка необязательна и содержит три записи по 3,5 секунды:

1. Закрытый рот.
2. Открытый рот без высунутого языка.
3. Высунутый язык.

Первые 0,9 секунды каждого шага отведены на подготовку. Для шага нужны минимум 7 пригодных наблюдений, сохраняются последние 20. Обе первые позы образуют отрицательный класс.

Дескриптор содержит **107 чисел**: сетка 5×5 с четырьмя цветовыми значениями на ячейку, четыре агрегата и три слабо взвешенных признака геометрии рта. Цвета нормируются относительно щёк. Изображения в профиль не записываются.

При создании профиля проверяются размерность, конечность значений и разделимость классов. При inference сначала проверяется расстояние до обучающих примеров. Слишком далёкий кадр возвращает `undefined`. Иначе вычисляется среднее RMS-расстояние до трёх ближайших образцов каждого класса:

```text
score = distance_to_negative / (distance_to_negative + distance_to_positive)
```

Раздельное сравнение с соседями не усредняет закрытый и открытый рот в один искусственный эталон. Если профиль передан, скрытого отката к цветовой эвристике нет.

### Подтверждение во времени

- Нужны минимум два наблюдения со score `>= 0.6` среди последних четырёх за 300 мс.
- После подтверждения допускается короткий пропуск положительных кадров до 450 мс.
- Три последовательных явных отрицательных наблюдения снимают подтверждение.
- Отсутствующий crop/лицо, невалидное время или большой разрыв кадров сбрасывают состояние.
- Один изолированный положительный кадр ограничивается значением 0.4 и не выбирает мем с языком.

В диагностике crop показан локально, а причина и score относятся к пиксельному/персональному анализу до временного подтверждения. Панель общих сигналов показывает последующий сглаженный признак, поэтому значения могут различаться.

## 5. Калибровка лица и сглаживание

Нейтральная калибровка записывает медиану измерений за короткую неподвижную позу. Она корректирует базовое открытие рта, глаз и наклон головы. Руки и язык не вычитаются из нейтрального лица.

Обновление в `App.tsx`:

```ts
previous = smoothFeatures(previous, normalizeFace(current, neutral), 0.5)
```

EMA применяется только к доступным текущим наблюдениям. Исчезнувшие признаки удаляются, а не сохраняются бессрочно. Для языка перед EMA работает отдельное подтверждение во времени.

## 6. Сопоставление с мемами

Каждая запись в `src/data/cats.ts` содержит изображение, вручную размеченные целевые признаки и необязательные `requiredFeatures`. Это аналогия с человеческой позой; выходы MediaPipe на фотографии кота не вычисляются.

### Обычные позы

Для пересечения доступных признаков кадра и эталона:

```text
d_rms = sqrt(sum(w_i × (observed_i - target_i)²) / sum(w_i))
coverage_penalty = 0.12 × (expected_count - compared_count) / expected_count
distance = min(1, d_rms + coverage_penalty + contradiction_penalty)
```

Веса: рот 3, глаза 1, наклоны головы 0.7, положение рук/близость 0.5, жесты/язык 5. Для обычной позы нужны минимум два сравнимых признака. Сильная неаннотированная сигнатура добавляет штраф 0.5.

Оценка вычисляется в прямом и зеркальном варианте с перестановкой left/right hand, затем выбирается меньшая. Это позволяет показать жест любой рукой.

### Сигнатурные ветки

- В режимах `combined`/`pose` уверенный требуемый жест `>= 0.6` оценивается сам по себе, без сравнения лица. Например, для 🤙 не нужны язык, рот или поднятое плечо.
- В `combined`/`face` подтверждённый язык `>= 0.6` выбирает соответствующую запись независимо от глаз и наклона головы. В `combined` уверенный жест получает приоритет над языком.
- Режим `face` игнорирует требования рук; `pose` исключает язык из сравниваемых признаков.

Distance является инженерной мерой для сортировки, не вероятностью. Число 0.8 у геометрического жеста тоже не означает «80% точности».

### Смена результата

Кандидат должен иметь distance меньше 0.65. Если предыдущий результат почти не хуже лучшего (разница меньше 0.015), он сохраняется. `MatchStabilizer` принимает первый результат сразу, но требует 350 мс непрерывного нового кандидата для замены. `null` сбрасывает выбор.

## 7. Overlay и экспорт

Рисование разметки отделено от вычисления признаков. Canvas имеет исходные размеры видео; оба слоя зеркалятся CSS одинаково. Рамки и соединения строятся только по доступным точкам. Отключение overlay не останавливает inference.

Экспорт использует Canvas: зеркальный кадр слева, картинка кота справа. Overlay добавляется по переключателю. PNG создаётся и скачивается в браузере по действию пользователя.

## 8. Загрузка и хранение

Production-сборка создаёт gzip-представления `.task` и `.wasm`, разбитые на части по 32 КиБ с JSON-манифестом. Загрузчик делает до шести запросов одновременно, проверяет размер частей, повторяет сбои и собирает исходный файл через `DecompressionStream`. Без манифеста используется загрузка целого файла.

Профиль и нейтральная калибровка хранятся в `localStorage`. Старые локальные замены картинок читаются из IndexedDB. Модели, JS и картинки запрашиваются с origin приложения. Видео, crop и текущие landmarks не отправляются серверу.

## 9. Как оценивать качество

Существующие тесты проверяют контракт моделей, известные геометрические/пиксельные случаи и последовательности кадров. Они не оценивают обобщение на новые камеры.

Для следующего этапа нужен размеченный набор с разделением по людям и устройствам, включая закрытый рот, зевок, улыбку, зубы, язык, помаду и перекрытия. Полезные метрики:

- precision/recall и confusion matrix для языка и каждого жеста;
- top-1/top-3 подбора;
- время до первого правильного результата;
- ложные переключения в минуту;
- p50/p95 времени inference и стартовой загрузки;
- доля кадров с отсутствующим наблюдением.

До такой оценки численная точность распознавания не заявляется.
